为什么先写 Markdown 再做 HTML

教学设计说明

读者：需要审阅 AI 文档的人。目标：分清内容来源和展示形式。用静态流程图说明修改应回到哪里；本例不需要动画或参数控件。

先把内容写清楚

Markdown 保存能独立阅读的解释、事实和限定。HTML 提供适合屏幕阅读的布局。需要修正结论时，先修改 Markdown，再同步 HTML，避免两份内容说法不一。

改写为什么需要核对

可选的 Gemini 改写发生在 HTML 生成之前。它只调整表达；日期、数字、否定和适用条件必须保留。原稿应单独保存，改写稿通过核对后才成为接受的 Markdown。本例没有调用 Gemini。

媒体 M1：静态工作流程图。沿箭头观察改写被拒绝时回到草稿，通过时进入 HTML。流程是示意，不代表模型调用已经完成。

哪些检查仍需要人判断

文件摘要可以判断源稿是否变化，不能证明内容正确。读者仍要核对事实、限定条件和图中的关系。此流程不保证学习效果，也不保证改写必然改善文字。
